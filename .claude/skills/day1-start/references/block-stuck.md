# 막혔을 때

> 언제든 호출된다. 사용자가 도움을 요청하거나 진행이 멈췄을 때.

## EXPLAIN

혼자 하다 막히는 건 정상이다. 세션에서도 절반 이상이 설치와 로그인에서 막혔다.

중요한 건 **막힌 지점을 넘기느냐가 아니라, 막힌 지점을 기록하느냐**다. 막히는 데는 두 종류가 있다.

- **요청이 애매해서 막힌 것** — 다시 물어보면 풀린다
- **계속 같은 데서 막히는 것** — 개인이 넘을 수 없는 벽이다. 권한, 계정, 접근 제한 같은 것

두 번째는 정확히 적혀 있어야 조직이 다룰 수 있다.

## EXECUTE

**1. 먼저 한 번 풀어본다**

무엇을 하려다 막혔는지 듣고, 해결 가능한 것이면 해결한다.

**2. 성격을 가른다**

해결됐으면 그대로 진행하되 기록에 남긴다. 해결되지 않으면 아래를 확인한다.

- 권한이 없어서인가
- 계정·구독 문제인가
- 회사가 막아둔 것인가
- 방법을 아직 몰라서인가

**3. 결산 파일에 적는다**

`work-cards/<날짜>-day1.md`의 `## 막힌 것` 절에 한 줄 추가한다. 권한·계정·회사 제한이면 `## 혼자 못 풀 것 같은 것` 절에도 넣는다.

**4. 슬랙에 올릴 문구를 만들어준다**

정리를 사용자에게 맡기지 않는다. 그대로 복사할 수 있게 만들어서 준다.

```
[막힌 것]
· 하려던 것:
· 막힌 지점:
· 시도해본 것:
· 성격: 권한 / 계정 / 회사 제한 / 방법 모름
```

**5. 그다음 안내**

권한·계정·회사 제한이면 여기서 더 붙잡지 않는다. 개인이 못 넘는 벽이므로 기록만 하고 다음으로 넘어간다.
