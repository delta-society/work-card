# Block 3: 인수인계서 일곱 줄

> 세션에서 `/init`으로 초안까지 만들었다. 오늘은 그 안을 채운다.

## EXPLAIN

우리 팀에 아주 유능한 신입이 왔다고 하자. 머리도 좋고 일도 빠르다. 첫날 뭘 안 하면 일이 안 될까.

메신저 초대, 자료 공유, 회의 참석 — 전부 **맥락을 주는 일**이다. 능력이 아무리 좋아도 우리 팀이 뭘 하는지 모르면 일을 못 한다.

AI도 똑같다. 성능이 부족한 게 아니라 맥락이 없는 것이다.

`/init`으로 만든 `CLAUDE.md`는 폴더 구조만 훑은 껍데기다. 여기에 **내가 어떤 일을 하는 사람인지**가 들어가야 다음 대화부터 자동으로 읽힌다.

**완벽하게 쓰지 않는다.** 지금 떠오르는 만큼만 쓰고 나머지는 AI가 되묻게 한다.

## EXECUTE

현재 `CLAUDE.md`를 읽어서 보여준 뒤, 아래 일곱 줄을 채운다.

```
1. 나는 누구인가          — 팀 / 맡은 일
2. 내가 매주 반복하는 일   — 한 가지만
3. 그 일에 쓰는 자료       — 어디서 오는가
4. 결과를 보는 사람        — 누구에게 가는가
5. 좋은 결과의 기준        — 무엇이 갖춰져야 통과인가
6. 추측하면 안 되는 것     — 모르면 반드시 물어야 할 것
7. 결과물 형식            — 표 / 문단 / 길이 / 말투
```

**한 번에 다 묻지 않는다.** 두세 줄씩 끊어서 묻고, 답을 받으면 그때 다음을 묻는다.

**6번이 가장 중요하다.** AI가 그럴듯한 오답을 내놓는 것을 막는 자리가 여기다.

다 받으면 기존 `CLAUDE.md`에 반영해서 쓰고, 바뀐 내용을 보여준다.

마지막으로 되묻게 한다.

```
내가 준 정보 중에 부족한 게 뭐야? 나한테 되물어봐
```

### 진행 규칙

- **대신 채우지 않는다.** 막히면 한 번만 되묻는다: *"지난주에 그 일 하셨죠? 그때 기준으로 얘기해주세요."*
- 2번이 뭉뚱그려지면 좁힌다 — 다음 블록에서 이 업무를 실제로 다룬다
- 5·6번이 얇으면 한 번 더 판다. 이 두 줄이 수요일 재료가 된다
- 모르는 줄은 `(아직 모름)`으로 둔다. **억지로 채운 줄이 빈 줄보다 나쁘다**
- 사용자 표현을 살린다. "정리한다"를 "데이터 가공"으로 바꾸지 않는다

## CHECK

```json
AskUserQuestion({
  "questions": [{
    "question": "어느 줄이 제일 쓰기 어려우셨나요?",
    "header": "인수인계서",
    "options": [
      {"label": "5번 — 좋은 결과의 기준", "description": "뭘 통과로 볼지"},
      {"label": "6번 — 추측하면 안 되는 것", "description": "반드시 물어야 할 것"},
      {"label": "2번 — 매주 반복하는 일", "description": "하나로 좁히기"},
      {"label": "다 무난했다", "description": "다음으로"}
    ],
    "multiSelect": false
  }]
})
```

**어느 답이든 그 자체가 재료다.** 1·2번을 고르면:

> "그게 수요일에 다룰 내용입니다. 무엇을 좋은 결과로 볼 것인가 — 오늘 여기서 걸린 게 정확히 그 자리입니다."

답을 기억해뒀다가 Block 5 결산에 반영한다.
