# Block 2: 내 업무로 만들고 스킬화 — 오늘의 핵심

> 세션에서 아무도 못 해본 것이 **스킬 만들기**다. 오늘 이거 하나만 되어도 성공이다.
> 완성이 목적이 아니다. 만들다 막힌 지점이 수요일 재료다.

## EXPLAIN

지금까지는 AI에게 **설명**했다. 이제 실제로 **만든다.**

두 단계다.

1. **산출물 하나 만들기** — 평소 만드시는 것 중 하나
2. **그걸 스킬로 고정하기** — 다음 달에 같은 일을 할 때 처음부터 다시 설명하지 않아도 된다

두 번째가 핵심이다. 스킬은 남이 만든 걸 실행해보는 게 아니라 **내 작업에서 나오는 것**이다.

## EXECUTE

### 1단계 — 무엇을 만들지 정한다

Block 1의 2번 줄을 그대로 가져와 확인한다.

```
인수인계서에 <업무>라고 쓰셨는데, 그거 한 번 만들어볼까요?
```

**Block 1을 건너뛰고 왔으면** 여기서 직접 묻는다.

```
매주 반복해서 하시는 일 중에 하나만 꼽으면 뭘까요?
```

다른 걸 원하면 그걸로 한다. **작을수록 좋다** — 크면 오늘 안에 안 끝난다.

### 2단계 — 실제로 만든다

재료(파일, 지난번 결과물, 자료)가 있으면 그걸 쓴다.

- 로컬에 있으면 읽어서 쓴다
- 없으면 사용자에게 내용을 물어 받는다
- **여기서 막히면 결산 파일에 적는다** — 자료 접근이 안 되는 것 자체가 중요한 발견이다

만드는 도중 판단이 필요한 지점이 나오면 **사용자에게 묻는다.** 대신 정하지 않는다.

결과를 보여주고 고칠 데를 받는다. 고치고 다시 보여준다. 사용자가 "이 정도면 됐다"고 하거나 더 못 가겠다고 할 때까지.

### 3단계 — 스킬로 만든다

**완성이 안 됐어도 이 단계는 한다.** 만들다 만 것도 레시피가 된다.

`.claude/skills/<짧은이름>/SKILL.md`를 만든다. 아래를 담는다.

- 무엇을 만드는 작업인가
- 어떤 재료가 필요한가 (없어서 못 쓴 것도 적는다)
- 어떤 순서로 하는가
- **사용자에게 물어야 하는 지점** — 판단이 필요했던 곳
- 무엇이 갖춰지면 끝인가 (Block 1의 5번 줄)

만든 뒤 파일을 보여주고, 어느 부분이 어디서 왔는지 한 줄로 짚어준다.

### 4단계 — 돌려본다

```
/<짧은이름>
```

같은 창에서 바로 쳐볼 수 있다. 어긋나는 데가 나오면 **말로 고친다.**

```
<어긋난 부분>을 이렇게 바꿔줘
```

시간이 없으면 넘어간다.

## CHECK

```json
AskUserQuestion({
  "questions": [{
    "question": "어디까지 가셨나요?",
    "header": "진행",
    "options": [
      {"label": "산출물도 스킬도 만들었다", "description": "완주"},
      {"label": "스킬은 만들었는데 산출물이 아쉽다", "description": "괜찮습니다"},
      {"label": "만들다가 재료가 없어서 막혔다", "description": "중요한 발견입니다"},
      {"label": "어디부터 시켜야 할지 막막했다", "description": "그것도 재료입니다"}
    ],
    "multiSelect": true
  }]
})
```

**3·4번이 1번보다 중요한 답일 수 있다.**

- 3번: "그게 오늘 제일 큰 수확입니다. 어떤 자료가 어디 있어야 하는지가 드러난 겁니다."
- 4번: "무엇을 시킬지가 안 정해진 겁니다. 그게 수요일에 다룰 내용입니다."

1번이면:

> "세션에서 아무도 못 만든 게 스킬입니다. 내일 새 대화에서 `/<이름>` 한번 쳐보세요."

답을 결산 파일에 적고, 다음 블록으로 갈지 묻는다.
