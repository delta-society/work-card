# Block 5: 슬랙에 올릴 결산

> 사용자가 정리하게 두지 않는다. **그대로 복사할 수 있는 문구를 만들어서 준다.**

## EXPLAIN

오늘 한 것을 슬랙에 남긴다. 이게 수요일 세션 설계의 입력이다.

잘 쓸 필요 없다. **안 된 것이 된 것보다 중요하다.**

## EXECUTE

진행 중 기록해둔 막힘들을 모으고, 아래 형식으로 정리해서 보여준다.

```markdown
[Day 1 실습 결산]

■ 만든 것
· 산출물: <무엇을 만들었는지 / 어디까지 갔는지>
· 스킬: /<이름>  (또는 "못 만듦 — <이유>")

■ 막힌 것
· <하려던 것> → <막힌 지점>
· <하려던 것> → <막힌 지점>

■ 혼자 못 풀 것 같은 것
· <권한·계정·회사 제한으로 분류된 것>

■ 수요일에 다뤄줬으면 하는 것
· <사용자 답변>
```

`work-cards/<날짜>-day1.md`로도 저장하고 경로를 알려준다.

**막힌 게 하나도 없으면** 한 번 더 확인한다: *"진행하면서 '이건 좀 아닌데' 싶었던 순간 없으셨어요?"* 그래도 없으면 없는 대로 적는다.

## CHECK

```json
AskUserQuestion({
  "questions": [{
    "question": "수요일에 뭘 다뤄줬으면 하세요?",

      {"label": "무엇을 시킬지 정하는 법", "description": "막막했다"},
      {"label": "만든 걸 팀에서 같이 쓰는 법", "description": "공유"},
      {"label": "오늘 막힌 것 해결", "description": "구체적인 문제"}
    ],
    "multiSelect": true
  }]
})
```

답을 결산 마지막 줄에 넣고 마무리한다.

```
위 내용을 그대로 슬랙에 올려주세요.

수요일 세션은 미리 짜여 있지 않습니다.
올려주신 걸로 정합니다.

내일 아침에 한 번 열어보시길 권합니다.
이틀 지나면 대부분 다시 안 엽니다.
```

시간과 여력이 있으면 Block 6(맥락 연동)을 권할 수 있다. 권하지 않아도 된다.
