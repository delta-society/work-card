# Block 6: 맥락을 도구에 연결하기

> 자료 14장(MCP) 대응. Block 4까지의 연장선이다.
> **여기까지 못 가도 1회차는 완료다.** 시간이 남았을 때만 연다.

## EXPLAIN

지금까지는 내가 아는 것을 **말로 옮겨** AI에게 줬다. 인수인계서 일곱 줄, 레시피 설명.

그런데 일에 필요한 재료 상당수는 이미 어딘가에 있다. 메신저 대화, 문서, 일정, 이슈 목록. 그걸 매번 복사-붙여넣기 하면 5분이면 지쳐서 결국 안 하게 된다 — 자료 10장에서 본 그 문제다.

**MCP는 그 도구를 AI에게 직접 연결하는 표준 규격이다.** 한 번 연결해 두면 AI가 필요한 맥락을 스스로 가져온다.

```
"메신저에서 지난주 논의 읽어줘"
        │
        ▼  도구 호출
┌──────────┐   MCP 표준   ┌──────────┐
│  Claude  │ ◀═════════▶ │   외부    │
│   Code   │              │  서비스   │
└──────────┘              └──────────┘
  내 컴퓨터                  회사 도구
```

### 오늘 할 것과 안 할 것

**할 것** — 지금 어떤 도구가 연결돼 있는지 보고, 하나만 시험 삼아 붙여본다.

**안 할 것** — 회사 계정·사내 시스템 연결. **연결 범위는 회사가 허용한 만큼**이고, 무엇을 연결할지는 오늘 결정하지 않는다. 자료 14장에 그렇게 적혀 있다.

## EXECUTE

**1. 지금 상태 보기** — 터미널에서

```
claude mcp list
```

아무것도 없으면 "No MCP servers configured"가 나온다. 정상이다.

**2. 무엇을 연결하고 싶은지 정리하기**

Claude에게 물어본다.

```
내 CLAUDE.md를 보고, 내 업무에서 AI가 직접 읽어오면 좋을 자료가 뭔지 알려줘.
각각 회사 승인이 필요한지도 구분해줘
```

3번 줄(그 일에 쓰는 자료)에 적어둔 것들이 후보로 나온다.

**3. 연결 방법 물어보기**

```
그중 하나를 MCP로 연결하려면 어떻게 해야 하는지 알려줘
```

명령 형태는 대개 이렇다. **지금 당장 실행하지 않는다** — 무엇을 연결할지가 정해진 다음이다.

```
claude mcp add --transport http <이름> <주소>
claude mcp add <이름> -- npx <서버-패키지>
```

연결한 뒤에는 `claude mcp list`로 확인하고, `claude mcp get <이름>`으로 상세를 본다.

### 진행 규칙

- **사용자가 회사 계정 정보를 입력하려 하면 멈춘다.** "그건 승인 절차를 확인한 다음에 하시는 게 맞습니다"라고 안내한다
- 실제 연결까지 못 가도 된다. **무엇을 연결하고 싶은지 목록이 나온 것까지가 오늘 성과**다
- 연결하고 싶은 것 중 승인이 필요한 항목은 따로 적어둔다 — 세 줄 결산 3번에 들어간다
