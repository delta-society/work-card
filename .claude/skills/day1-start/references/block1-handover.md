# Block 1: 인수인계서 일곱 줄

> 세션에서 `/init`으로 초안까지 만들었다. 오늘은 그 안을 채운다.
> **한 줄씩 묻는다.** 일곱 줄을 나열하고 "채워보세요"라고 하면 안 된다.

## EXPLAIN

우리 팀에 아주 유능한 신입이 왔다고 하자. 머리도 좋고 일도 빠르다. 첫날 뭘 안 하면 일이 안 될까.

메신저 초대, 자료 공유, 회의 참석 — 전부 **맥락을 주는 일**이다. 능력이 아무리 좋아도 우리 팀이 뭘 하는지 모르면 일을 못 한다.

AI도 똑같다. 성능이 부족한 게 아니라 맥락이 없는 것이다.

`/init`으로 만든 `CLAUDE.md`는 폴더 구조만 훑은 껍데기다. 여기에 **내가 어떤 일을 하는 사람인지**가 들어가야 다음 대화부터 자동으로 읽힌다.

**완벽하게 쓰지 않는다.** 지금 떠오르는 만큼만 답하면 된다.

## EXECUTE

현재 `CLAUDE.md`를 읽어 지금 뭐가 적혀 있는지 한 줄로 알려주고 시작한다.

### 묻는 순서 — 한 번에 하나씩

**1번**
```
어느 팀에서 어떤 일 하고 계세요?
```

**2번** — 오늘의 중심이다. 여기서 나온 업무를 Block 2에서 실제로 만든다.
```
매주 반복해서 하시는 일 중에 하나만 꼽으면 뭘까요?
```
여러 개를 말하면 **가장 최근에 한 것**으로 좁힌다. 기억이 살아 있는 쪽이 재료가 많다.

**3번**
```
그 일 하실 때 뭘 여세요? 자료는 어디서 가져오시고요?
```
한 개만 말하면 한 번 되묻는다: *"그거 열고 나서 또 뭐 보세요?"*

**4번**
```
결과물은 누구한테 가나요?
```

**5번** — 직접 물으면 대부분 막힌다. **반례부터** 묻는다.
```
그 결과물 중에 예전에 "이건 좀 아닌데" 싶었던 적 있으세요? 뭐가 문제였어요?
```
답이 나오면 뒤집어 정리해준다: *"그럼 <반대>가 갖춰지면 통과인 거네요."*

**6번** — 가장 중요하다.
```
AI가 혼자 짐작하면 안 되는 건 뭘까요?
모르면 반드시 저한테 물어봐야 하는 것.
```
막히면: *"틀린 숫자나 이름이 들어가면 큰일 나는 게 있나요?"*

**7번**
```
결과물은 보통 어떤 형태인가요? 표인지 문단인지, 길이나 말투는요.
```

### 파일에 반영

일곱 줄을 다 받으면 기존 `CLAUDE.md`에 반영해서 쓰고, **바뀐 내용을 보여준다.**

그다음 되묻게 한다.

```
내가 준 정보 중에 부족한 게 뭐야? 나한테 되물어봐
```

### 진행 규칙

- **대신 채우지 않는다.** 되묻기는 한 번, 실제 사례를 떠올리게 하는 방식으로
- 5·6번이 얇으면 한 번 더 판다. 이 두 줄이 수요일 재료가 된다
- 모르는 줄은 `(아직 모름)`으로 둔다
- 사용자 표현을 살린다. "정리한다"를 "데이터 가공"으로 바꾸지 않는다
- 막히는 지점이 나오면 그때그때 `work-cards/<날짜>-day1.md`에 적는다
