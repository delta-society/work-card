# Day 1 실습 — 혼자 진행하는 파트

세션에서 설치·로그인·`/init`까지 했다. 여기서부터는 혼자 한다.

**오늘 목표 한 줄** — 매주 잃고 있는 시간 하나를, AI가 읽을 수 있는 형태로 옮겨 놓는 것.

## 이 스킬의 성격

시범을 따라 하는 교보재가 아니다. **사용자 본인의 업무로 실제 산출물과 스킬이 나와야** 끝난다. 예시 업무로 진행하거나 사용자 대신 내용을 채워서는 안 된다.

---

## 진행 규칙 — 절대 위반 금지

> 이 규칙이 최우선이다. 위반하면 실습이 강의가 된다.

```
┌─ 이 스킬은 "대화가 곧 실습"이다 ────────────────────────┐
│                                                          │
│ 사용자를 다른 창으로 보내지 않는다.                        │
│ 여기서 같이 만든다.                                       │
│                                                          │
│ ✅ 질문 하나 → 답 받기 → 다음 질문                        │
│ ✅ 사용자가 말한 것으로 파일을 만들어준다                   │
│ ✅ 만든 것을 보여주고 고칠 데를 받는다                     │
│                                                          │
│ ❌ 질문 여러 개를 한 번에 던지기                           │
│ ❌ "이렇게 해보세요" 하고 물러나기                         │
│ ❌ 사용자가 막힐 때 예시를 던져 대신 채우기                 │
│ ❌ 블록 여러 개를 한 턴에 몰아서 진행하기                   │
└──────────────────────────────────────────────────────────┘
```

### 질문은 한 번에 하나

일곱 줄을 한 번에 나열하고 "채워보세요"라고 하면 안 된다. 한 줄 묻고, 답을 받고, 그 답을 되읽어준 뒤 다음 줄로 간다.

여러 줄을 묶어 물어야 할 때도 **최대 두 줄까지**다.

### 막히면 되묻되 답을 주지 않는다

사용자가 "글쎄요", "잘 모르겠는데"라고 하면 **한 번만** 되묻는다. 실제 사례를 떠올리게 하는 방식으로.

> "지난주에 그 일 하셨죠? 그때 기준으로 얘기해주세요."

그래도 안 나오면 `(아직 모름)`으로 두고 넘어간다. **억지로 채운 칸이 빈 칸보다 나쁘다.**

### 블록 사이에는 반드시 확인한다

한 블록이 끝나면 CHECK 섹션대로 확인하고, AskUserQuestion으로 다음 블록에 갈지 묻는다. 사용자 확인 없이 다음 블록으로 넘어가지 않는다.

| 블록 | 파일 | 내용 | 시간 |
|------|------|------|------|
| — | `references/block-stuck.md` | **막혔을 때** · 언제든 호출 | — |
| 1 | `references/block1-handover.md` | **인수인계서 일곱 줄** (`CLAUDE.md` 채우기) | 15분 |
| 2 | `references/block2-build.md` | **내 업무로 만들고 스킬화** ← 핵심 | 30분 |
| 3 | `references/block3-wrap.md` | 슬랙에 올릴 결산 | 5분 |

> 각 파일은 `## EXPLAIN`, `## EXECUTE`, `## CHECK` 섹션으로 되어 있다.
> **한 번에 한 파일만 읽는다.** 미리 여러 개 읽으면 블록이 뭉개진다.

## 상시 규칙 — 막힘은 파일에 적는다

진행 중 막히거나, 오류가 나거나, 원하는 대로 안 될 때마다 **그 자리에서 `work-cards/<오늘날짜>-day1.md`의 `## 막힌 것` 절에 한 줄 추가한다.** 기억에 담아두지 않는다 — 대화가 길어지면 Block 3에서 놓친다.

```markdown
- <하려던 것> → <막힌 지점>
```

사용자가 "이거 왜 안 되지", "잘 모르겠다", "안 되네" 같은 반응을 보이면 그것도 막힘으로 센다. 사용자가 도움을 요청하면 `references/block-stuck.md`를 읽고 그에 따른다.

## 끝나면 손에 남는 것

- `CLAUDE.md` — 일곱 줄이 채워진 내 인수인계서
- **내 업무 산출물 하나** — 완성 아니어도 됨
- **`.claude/skills/<내업무>/SKILL.md`** — 그 작업에서 나온 내 스킬
- `work-cards/<날짜>-day1.md` — 슬랙에 그대로 붙여넣을 결산

## 완료 기준

세 블록 전부. 그중 **Block 2가 핵심** — 세션에서 아무도 못 만들어본 것이 스킬이다.

산출물이 완성되지 않아도 된다. **어디서 막혔는지가 수요일 세션의 재료**다.

## 하지 않는 것

- 예시 업무로 진행하기 — 반드시 사용자 본인 업무여야 한다
- 사용자 대신 내용 채워주기
- 회사 계정·사내 시스템 실제 연결 — 승인 절차가 먼저다

## 시작

### 1. 환경 확인 (묻지 말고 직접 확인한다)

```
!pwd
```

로 현재 폴더를 확인하고, `CLAUDE.md`와 `.claude/skills/` 존재 여부를 본다.

**`CLAUDE.md`가 없으면** — 폴더가 틀렸을 가능성이 크다. 세션에서 `~/dev/<이름>` 형태로 만들었다.

```
지금 폴더에 CLAUDE.md가 안 보입니다.
세션 때 만드신 폴더가 맞을까요?

터미널에서 이렇게 이동한 뒤 다시 열어주세요.

  cd ~/dev/<폴더이름>
  claude
```

폴더 이름을 모르면 `!ls ~/dev`로 찾아준다. `~/dev` 자체가 없으면 **여기서 만들지 말고** 사용자에게 어느 폴더에서 작업했는지 묻는다.

**`CLAUDE.md`가 있으면** 내용을 읽어 일곱 줄이 채워졌는지 확인하고 다음으로 간다.

### 2. 오늘 할 것 안내

```
세션에서 설치와 CLAUDE.md 초안까지 하셨습니다.
여기서부터는 같이 하시면 됩니다.

  1. 인수인계서 일곱 줄 채우기   (15분)
  2. 내 업무로 만들고 스킬화     (30분) ← 오늘의 핵심
  3. 슬랙에 올릴 결산            (5분)

다른 창으로 옮기실 필요 없습니다. 여기서 같이 만듭니다.
```

### 3. 결산 파일 먼저 만든다

`work-cards/<오늘날짜>-day1.md`를 지금 만든다. 막힘을 그때그때 적을 자리가 필요하다.

```markdown
# Day 1 실습 — <날짜>

## 만든 것

## 막힌 것

## 혼자 못 풀 것 같은 것
```

### 4. 시작 지점을 묻는다

```json
AskUserQuestion({
  "questions": [{
    "question": "어디서부터 시작할까요?",
    "header": "시작",
    "options": [
      {"label": "1번부터 순서대로", "description": "인수인계서부터"},
      {"label": "2번 — 바로 만들기부터", "description": "시간이 없다"},
      {"label": "막힌 게 있어요", "description": "그것부터 봅니다"}
    ],
    "multiSelect": false
  }]
})
```

"막힌 게 있어요"면 `references/block-stuck.md`로 간다.

**2번을 고르면** 한 번만 이렇게 권한다: *"1번을 5분만 먼저 하시면 2번 결과가 확 달라집니다. 그래도 바로 가실까요?"* 그래도 2번을 원하면 따르되, Block 2 시작에서 업무를 직접 묻는다.
