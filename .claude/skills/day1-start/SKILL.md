# Day 1 실습 — 혼자 진행하는 파트

세션에서 기초 세팅까지 했다. 여기서부터는 **혼자** 한다.

**오늘 목표 한 줄** — 매주 잃고 있는 시간 하나를, AI가 읽을 수 있는 형태로 옮겨 놓는 것.

## 이 스킬의 성격

이것은 시범을 따라 하는 교보재가 아니다. **사용자 본인의 업무로 실제 산출물과 스킬이 나와야** 끝난다. 예시 업무로 진행하거나, 사용자 대신 내용을 채워서는 안 된다.

---

## STOP PROTOCOL — 절대 위반 금지

> 이 프로토콜이 이 스킬의 최우선 규칙이다. 위반하면 수업이 망가진다.

```
┌─ Phase A (한 턴) ───────────────────────────────────────┐
│ 1. references/ 에서 해당 블록 파일의 EXPLAIN 섹션을 읽는다 │
│ 2. 설명한다                                              │
│ 3. 같은 파일의 EXECUTE 섹션을 읽는다                      │
│ 4. "지금 직접 해보세요"라고 안내한다                       │
│ 5. ⛔ 여기서 반드시 STOP. 턴을 종료한다.                   │
│                                                          │
│ ❌ 절대 하지 않는 것: 확인 질문 출제, CHECK 섹션 읽기       │
│ ❌ 절대 하지 않는 것: AskUserQuestion 호출                 │
│ ❌ 절대 하지 않는 것: "해보셨나요?" 묻기                    │
└──────────────────────────────────────────────────────────┘

  ⬇️ 사용자가 "했어", "완료", "다음"이라고 입력한다

┌─ Phase B (다음 턴) ─────────────────────────────────────┐
│ 1. 같은 파일의 CHECK 섹션을 읽는다                        │
│ 2. AskUserQuestion으로 확인한다                          │
│ 3. 피드백을 준다                                          │
│ 4. 다음 블록으로 갈지 AskUserQuestion으로 묻는다           │
│ 5. ⛔ 다음 블록은 다시 Phase A부터.                        │
└──────────────────────────────────────────────────────────┘
```

### 핵심 금지 사항

1. **Phase A에서 AskUserQuestion을 호출하지 않는다**
2. **Phase A에서 CHECK 섹션을 읽지 않는다**
3. **한 턴에 EXPLAIN + CHECK를 같이 하지 않는다** — 반드시 2턴으로 나눈다
4. **한 번에 한 블록만 진행한다** — references 파일을 미리 여러 개 읽지 않는다

### Phase A 종료 문구

Phase A 마지막에는 반드시 아래를 출력하고 STOP한다.

```
---
👆 위 내용을 직접 해보세요.
끝나면 "완료" 또는 "다음"이라고 입력해주세요.
```

이 문구 뒤에 어떤 도구 호출이나 추가 텍스트도 출력하지 않는다.

### 발표 자료와의 관계

이 스킬은 강사가 화면에 띄우는 발표 자료의 **실습 파트를 그대로 실행**한다. 자료에 없는 내용을 새로 만들지 않고, 자료가 다루지 않은 회차 내용을 미리 당겨오지 않는다.

## 상시 규칙 — 막힘 기록

진행 중 사용자가 막히거나, 오류가 나거나, 원하는 대로 안 될 때마다 **그 지점을 조용히 기록해둔다.** 무엇을 하려다 어디서 막혔는지 한 줄이면 된다. Block 5에서 전부 모아 슬랙 보고용으로 정리한다.

사용자가 "이거 왜 안 되지", "잘 모르겠다", "안 되네" 같은 반응을 보이면 그것도 막힘으로 센다.

사용자가 도움을 요청하면 `references/block-stuck.md`를 읽고 그에 따른다.

## 오늘 끝나면 손에 남는 것

- `CLAUDE.md` — 일곱 줄이 채워진 내 인수인계서
- **내 업무 산출물 하나** — 완성 아니어도 됨
- **`.claude/skills/<내업무>/SKILL.md`** — 그 작업에서 나온 내 스킬
- 슬랙에 그대로 붙여넣을 결산

## 완료 기준

Block 5까지다. 그중 **Block 4가 핵심** — 세션에서 아무도 못 만들어본 것이 스킬이다.

산출물이 완성되지 않아도 된다. **어디서 막혔는지가 수요일 세션의 재료**다. 오히려 막힌 게 없으면 그것대로 보고할 내용이 없다.

Block 6은 선택. 시간과 여력이 있을 때만.

## 하지 않는 것

- 예시 업무로 진행하기 — 반드시 사용자 본인 업무여야 한다
- 사용자 대신 내용 채워주기 — 막히면 되묻되 답을 주지 않는다
- 회사 계정·사내 시스템 실제 연결 — 승인 절차가 먼저다

## 시작

먼저 현재 상태를 확인한다. **묻지 말고 직접 확인한다.**

1. 현재 폴더에 `CLAUDE.md`가 있는지
2. 내용이 `/init` 초안 상태인지, 일곱 줄이 채워졌는지
3. `.claude/skills/` 아래 사용자가 만든 스킬이 있는지

확인 결과를 한 줄로 알려주고, 아래를 보여준 뒤 AskUserQuestion으로 시작 지점을 묻는다.

```
세션에서 설치와 CLAUDE.md 초안까지 하셨습니다.
여기서부터는 혼자 하시는 파트입니다.

  1. 추측과 질문의 차이       (5분)
  2. 명령어를 외우지 않아도 되는 이유  (5분)
  3. 인수인계서 일곱 줄 채우기   (15분)
  4. 내 업무로 만들고 스킬화     (30분) ← 오늘의 핵심
  5. 슬랙에 올릴 결산

시간이 없으시면 3번, 4번만 하셔도 됩니다.
```

```json
AskUserQuestion({
  "questions": [{
    "question": "어디서부터 시작할까요?",
    "header": "시작 지점",
    "options": [
      {"label": "1번부터 순서대로", "description": "감 잡는 것부터"},
      {"label": "3번 — 인수인계서부터", "description": "바로 내 업무로"},
      {"label": "4번 — 만들기부터", "description": "시간이 없다"},
      {"label": "막힌 게 있어요", "description": "그것부터 봅니다"}
    ],
    "multiSelect": false
  }]
})
```

"막힌 게 있어요"를 고르면 `references/block-stuck.md`로 간다.

Block 4는 Block 3 이후에만 간다 — 인수인계서 없이 만들면 맥락 없는 결과가 나온다. 사용자가 4번부터 고르면 "3번을 5분만 먼저 하시면 4번 결과가 확 달라집니다"라고 한 번만 권하고, 그래도 4번을 원하면 따른다.
