# 질문 5: 판단 지점 — 이 스킬의 핵심

> 여기가 work-card의 값어치다.
> 판단이 들어가는 지점 = 그 사람이 대체 불가능한 곳.
> 나머지 = 넘길 수 있는 것.
> 이 선이 그어지면 자동화할 것과 안 할 것이 저절로 갈린다.

## ASK

**q4에서 받은 단계들을 그대로 선택지로 만든다.** 미리 정해둔 옵션이 아니다 — 사용자 본인의 순서를 되돌려주는 것이다.

```json
AskUserQuestion({
  "questions": [{
    "question": "방금 말씀하신 단계 중에, '이건 내가 정해야 한다' 싶은 데가 어디예요?",
    "header": "판단 지점",
    "options": [
      {"label": "<q4의 1단계>", "description": "<그 단계 설명>"},
      {"label": "<q4의 2단계>", "description": "<그 단계 설명>"},
      {"label": "<q4의 3단계>", "description": "<그 단계 설명>"},
      {"label": "<q4의 4단계>", "description": "<그 단계 설명>"}
    ],
    "multiSelect": true
  }]
})
```

`multiSelect: true` — 여러 곳일 수 있다.
단계가 5개 넘으면 4개로 묶어서 제시한다.

⛔ STOP.

## PROBE

**답이 얇으면 반드시 한 번 더 판다. 이 질문만은 그냥 넘기지 않는다.**

```
그때 뭘 보고 정하세요? 기준 같은 게 있나요?
```

기준이 나오면 그게 곧 스킬에 들어갈 규칙이다.
"그냥 감으로"라고 하면 그것도 그대로 적는다 — **감으로 하는 판단이 바로 못 넘기는 판단**이고, 그게 이 사람이 남아야 하는 이유다.

## CAPTURE

- `판단 지점` 칸: 선택된 단계 + 기준
- 선택되지 **않은** 단계들 = `넘길 수 있는 것`

두 목록이 갈리는 순간을 사용자에게 짚어준다:

```
그럼 나머지 <n>개는 넘길 수 있는 부분이네요.
<판단 지점>은 계속 직접 보셔야 하는 거고요.
```
