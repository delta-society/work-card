# Work Card — 반복 업무를 스킬로

이 스킬이 호출되면 아래 **STOP PROTOCOL**을 반드시 따른다.

---

## STOP PROTOCOL — 절대 위반 금지

> 이 프로토콜은 이 스킬의 최우선 규칙이다.
> 위반하면 카드가 요약문이 되고, 이 스킬은 값어치를 잃는다.

### 질문 하나 = 턴 하나

```
┌─ Phase A (한 턴) ───────────────────────────────────────┐
│ 1. references/ 에서 해당 질문 파일의 ASK 섹션을 읽는다      │
│ 2. AskUserQuestion으로 질문 하나를 던진다                  │
│ 3. ⛔ 여기서 반드시 STOP. 턴을 종료한다.                   │
│                                                          │
│ ❌ 절대 하지 않는 것: 다음 질문 미리 꺼내기                 │
│ ❌ 절대 하지 않는 것: 사용자 대신 답 채우기                 │
│ ❌ 절대 하지 않는 것: "그러면 아마 이러시겠네요" 추측        │
└──────────────────────────────────────────────────────────┘

  ⬇️ 사용자가 답한다

┌─ Phase B (다음 턴) ─────────────────────────────────────┐
│ 1. 받은 답을 한 줄로 되읽어준다 ("○○이시군요")            │
│ 2. 답이 얇으면 해당 파일의 PROBE 섹션으로 한 번만 되묻는다  │
│ 3. 충분하면 다음 질문의 Phase A로 넘어간다                 │
└──────────────────────────────────────────────────────────┘
```

### 핵심 금지 사항

1. **한 턴에 두 개 이상 묻지 않는다** — 한꺼번에 물으면 사용자는 요약해서 답한다. 요약된 답에는 그 사람이 실제로 어떻게 일하는지가 빠진다. 이 스킬의 값어치는 그 빠지는 부분에 있다.
2. **막혀도 예시를 던져 채우지 않는다** — 기다린다. PROBE는 한 번만, 그것도 되묻기지 대신 답하기가 아니다.
3. **용어를 먼저 쓰지 않는다** — `워크플로우`, `트리거`, `인풋/아웃풋`, `병목`을 먼저 꺼내지 않는다. 사용자 언어로 묻고, 카드에 옮길 때 정리한다.
4. **PROBE는 질문당 최대 1회** — 두 번 되물으면 취조가 된다. 여전히 얇으면 `(아직 모름)`으로 넘어간다.

### 모르는 칸은 비워둔다

여섯 칸을 다 못 채워도 카드를 만든다. `(아직 모름)`으로 남긴다. 빈 칸이 다음에 무엇을 알아내야 하는지를 알려준다. **억지로 채운 칸이 빈 칸보다 나쁘다.**

> **한 번에 한 파일만 읽는다.** 여섯 개를 미리 읽으면 질문을 몰아서 하게 된다.

## 진행 순서

```
step0 업무 고르기
  ↓
q1 → q2 → q3 → q4 → q5 → q6      (각각 Phase A → Phase B)
  ↓
step7 카드 저장
  ↓
step8 스킬 생성 + 첫 실행
```

- 사용자가 "건너뛰자", "모르겠다"고 하면 `(아직 모름)`으로 두고 다음으로 간다
- 중간에 이전 답을 고치겠다고 하면 받아서 반영하고 원래 자리로 돌아온다

---

## 완료 기준

- `work-cards/` 아래 카드 파일 1개
- `.claude/skills/<짧은이름>/SKILL.md` 1개
- 사용자가 새 스킬을 최소 1회 실행

세 개가 다 돼야 끝이다. **카드만 만들고 끝내지 않는다** — 돌아가는 걸 봐야 자기 것이 된다.
