# work-card

> Medit 전략마케팅팀 AI 밀착 교육 3회차용 Claude Code 스킬.

회차마다 스킬 하나씩. 발표 자료(Session 1~3)의 실습 파트를 그대로 실행한다.

## 설치

```bash
npx skills add delta-society/work-card --agent claude-code --yes
```

한 번 설치하면 3개가 다 들어온다.

## 회차별

| 회차 | 실행 | 자료 대응 | 끝나면 남는 것 |
|---|---|---|---|
| 1 (월) | `/day1-start` | Session 1 실습(20~27장) | 환경 · `CLAUDE.md` 일곱 줄 · 레시피 시도 + 막힌 지점 |
| 2 (수) | `/day2-measure` | 무엇을 재는가 | 판정 기준 + 그 기준이 심긴 레시피 |
| 3 (금) | `/day3-handoff` | 첫 산출물 정리 + 인계 | 실제로 쓰는 레시피 + 인계 목록 |

**한 번에 하나씩 간다.** 앞 회차 산출물이 다음 회차 입력이고, 각 스킬은 앞 회차 결과물이 없으면 되돌려보낸다.

**2·3회차는 미리 짜여 있지 않다.** 자료 27장의 약속대로, 앞 회차 세 줄 결산이 다음 회차 설계다.

## 회차별 상세

### `/day1-start` — 첫 두 시간

| 블록 | 하는 것 |
|---|---|
| 0 | 구동 3줄 · 첫 대화 · `/config` Explanatory |
| 1 | 추측과 질문의 차이 — 같은 요청 두 번 |
| 2 | 명령어를 외우지 않아도 되는 이유 · `!` |
| 3 | **내 인수인계서 일곱 줄** (`CLAUDE.md`) |
| 4 | **반복 업무 하나를 레시피로** |
| 5 | 세 줄 결산 + 예측 회수 |

3번의 6번 줄(추측하면 안 되는 것)과 4번의 되묻기가 핵심이다. **레시피가 완성되지 않아도 된다** — 어디서 막히는지 확인하는 것까지가 1회차 몫이고, 막힌 지점이 2회차 재료다.

### `/day2-measure` — 무엇을 재는가

| 블록 | 하는 것 |
|---|---|
| 0 | 지난 이틀 — 두 번 실행해봤나 |
| 1 | 안 풀린 것 하나 다시 — 왜 안 풀렸는지 성격 가르기 |
| 2 | **좋은 결과의 기준** — 반례 → 통과선 → 우선순위 |
| 3 | 기준을 레시피에 심기 |
| 4 | 세 줄 결산 |

2번이 중심이다. 기준을 직접 물으면 막히므로 **반례부터** 묻는다("이건 아닌데 싶었던 적?"). "사람이 봐야만 판단된다"는 답이 나오면 레시피에 "여기서는 반드시 물어본다"로 심는다.

### `/day3-handoff` — 정리와 인계

| 블록 | 하는 것 |
|---|---|
| 0 | 이번 주에 실제로 썼나 |
| 1 | **실제 업무 건**으로 돌리고 기준으로 판정 |
| 2 | 남이 쓸 수 있게 |
| 3 | **혼자 못 푼 것 인계** |
| 4 | 3회 돌아보기 |

3번이 이 프로그램의 마지막 산출물이다. 막힌 것을 권한 / 데이터 / 협조 / 학습으로 갈라 적는다. 앞 셋은 개인이 못 넘는 벽이라 **"○○ 화면에서 △△를 받으려는데 열람 권한이 없다"**처럼 구체적으로 적어야 조직이 다룰 수 있다.

## 필요한 것

| 항목 | 확인 |
|---|---|
| Claude 구독 (Pro / Max / Teams / Enterprise) | 로그인 시 확인됨 |
| Claude Code | 터미널에 `claude` → 인사하면 성공 |
| Node.js | 터미널에 `npx -v` → 버전 나오면 OK |

Claude Code가 없다면 [claude.ai](https://claude.ai) 대화창에 "Claude Code 설치하는 방법 알려줘"라고 물어보면 환경에 맞게 안내해준다.

**터미널 여는 법** — Mac: `⌘ + Space` → "터미널" / Windows: 시작 → "PowerShell"

## 결과물

```
CLAUDE.md                              ← 내 인수인계서 (1회차)
work-cards/2026-07-27-<업무>.md        ← 회차별 세 줄 + 기준 + 인계 목록
.claude/skills/<업무>/SKILL.md          ← 내 레시피 (1~3회차에 걸쳐 완성)
```

## 설계 원칙

- **STOP PROTOCOL** — 블록마다 2턴. 설명+실행 안내 후 멈추고, 사용자가 돌아오면 확인 질문. 한 턴에 몰아서 하면 실습이 사라진다
- **AskUserQuestion** — 선택지를 주고 묻는다. 열린 질문만 던지면 "글쎄요"가 나온다
- **한 번에 한 파일** — references를 미리 여러 개 읽으면 블록이 뭉개진다
- **대신 답하지 않는다** — 막혀도 예시를 던져 채우지 않는다. 되묻기는 한 번, 그것도 "지난주에 하셨죠?"처럼 실제 사례를 떠올리게 하는 방식
- **용어를 먼저 쓰지 않는다** — 워크플로우·트리거·판정 기준 같은 말 없이 묻고, 정리할 때 붙인다
- **모르는 칸은 비워둔다** — 억지로 채운 칸이 빈 칸보다 나쁘다
- **자료에 없는 걸 만들지 않는다** — 발표 자료의 실습 파트를 실행하는 스킬이지, 별도 커리큘럼이 아니다
