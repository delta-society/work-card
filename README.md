# work-card

> 3회에 걸쳐, 매주 반복하는 업무 하나를 실제로 돌아가는 나만의 스킬로 만든다.

Claude Code 스킬 3개. 회차마다 하나씩 쓴다.

## 설치

```bash
npx skills add delta-society/work-card --agent claude-code --yes
```

한 번 설치하면 3개가 다 들어온다.

## 회차별

| 회차 | 실행 | 하는 것 | 끝나면 남는 것 |
|---|---|---|---|
| 1 | `/day1-start` | 켜기 · 감 잡기 · 내 업무 하나 고르기 | 돌아가는 환경 + 카드 절반 |
| 2 | `/day2-map` | 순서 펼치기 · **판단 지점 찾기** | 여섯 칸이 다 찬 카드 |
| 3 | `/day3-build` | 스킬 생성 · 돌려보기 · 고치기 | `/<내업무>` 하나 |

**한 번에 하나씩 간다.** 1회차에서 스킬을 만들지 않고, 3회차에서 업무를 새로 고르지 않는다. 앞 회차 결과물이 다음 회차의 입력이다.

## 필요한 것

| 항목 | 확인 |
|---|---|
| Claude 구독 (Pro / Max / Teams / Enterprise) | 로그인 시 확인됨 |
| Claude Code | 터미널에 `claude` → 인사하면 성공 |
| Node.js | 터미널에 `npx -v` → 버전 나오면 OK |

Claude Code가 없다면 [claude.ai](https://claude.ai) 대화창에 "Claude Code 설치하는 방법 알려줘"라고 물어보면 환경에 맞게 안내해준다.

**터미널 여는 법** — Mac: `⌘ + Space` → "터미널" / Windows: 시작 → "PowerShell"

## 핵심 — 판단 지점

2회차 Block 2가 이 프로그램의 중심이다.

내 업무의 순서를 펼쳐놓고, 그중 **"이건 내가 정해야 한다" 싶은 단계**를 고른다. 선택된 것은 판단 지점, 나머지는 넘길 수 있는 것으로 갈린다.

3회차에서 만들어지는 스킬은 이 선을 그대로 따른다.

- 넘길 수 있는 단계 → 스킬이 알아서 실행
- 판단 지점 → **스킬이 멈추고 나에게 물어봄**

이 구분 없이 만든 스킬은 사람이 정해야 할 것까지 AI가 정해버린다. 그럴듯하지만 내 판단이 아닌 결과가 나온다.

## 결과물

```
work-cards/2026-07-27-주간리포트.md      ← 업무 카드 (1·2회차)
.claude/skills/주간리포트/SKILL.md        ← 내 스킬 (3회차)
```

두 번째가 목적지다. 새 대화에서 `/주간리포트`를 치면 그 일이 돌아간다.

## 구조

```
.claude/skills/
├── day1-start/
│   ├── SKILL.md
│   └── references/
│       ├── block0-setup.md      # 터미널·Claude·첫 대화
│       ├── block1-feel.md       # 추측하는 AI vs 질문하는 AI
│       ├── block2-basics.md     # 명령어를 안 외워도 되는 이유
│       └── block3-pick.md       # 내 업무 고르기
├── day2-map/
│   ├── SKILL.md
│   └── references/
│       ├── block0-review.md     # 지난주 돌아보기
│       ├── block1-sequence.md   # 순서 펼치기
│       ├── block2-judgment.md   # 판단 지점 ← 핵심
│       └── block3-finish.md     # 완료·수신자 + 카드 완성
└── day3-build/
    ├── SKILL.md
    └── references/
        ├── block0-anatomy.md    # 스킬이 뭘로 되어 있나
        ├── block1-generate.md   # 내 카드를 스킬로
        ├── block2-run.md        # 돌려보기
        ├── block3-fix.md        # 말로 고치기
        └── block4-wrap.md       # 남은 것 정리
```

## 설계 원칙

- **STOP PROTOCOL** — 블록마다 2턴으로 나눈다. 설명+실행 안내 후 멈추고, 사용자가 돌아오면 확인 질문. 한 턴에 몰아서 하면 실습이 사라진다
- **AskUserQuestion** — 선택지를 주고 묻는다. 열린 질문만 던지면 "글쎄요"가 나온다
- **한 번에 한 파일** — references를 미리 여러 개 읽으면 블록이 뭉개진다
- **대신 답하지 않는다** — 막혀도 예시를 던져 채우지 않는다. 되묻기는 한 번, 그것도 "지난주에 하셨죠? 그때 뭐부터 하셨어요"처럼 실제 사례를 떠올리게 하는 방식
- **용어를 먼저 쓰지 않는다** — 워크플로우·트리거·병목 같은 말 없이 묻고, 카드에 옮길 때 정리한다
- **모르는 칸은 비워둔다** — 억지로 채운 칸이 빈 칸보다 나쁘다. 빈 칸이 다음에 알아낼 것을 알려준다
- **만들고 끝내지 않는다** — 3회차 완료 기준은 생성·실행·수정 세 가지 전부
